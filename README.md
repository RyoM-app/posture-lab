### IMU の途切れの原因（予備実験のデータから）

dual_test1・2 では、方向と加速度のイベントが**同じ時刻に同じ長さだけ**止まっていた（1回目：250 ms超が22回・最長5.0秒、2回目：6回・最長3.4秒）。イベント自体の時刻（`eventTimestamp`）も同じだけ空いていたので、ブラウザの処理が詰まって遅れたのではなく、イベントが発生していなかった。カメラのフレームはその間も処理されていた（途切れ0回）。ブラウザは iPhone の Chrome（CriOS 155、中身は WebKit）。

- 加速度の予備の経路は、方向だけが来ない場合には効くが、**この途切れは埋められない**（両方が同時に止まるため）
- 固定の回は、基準時の上向きで h を補う（`headInclinationFixedUp`）。スタンドが動いていないことは、IMUが届いている間の1°の判定で確かめる
- 手持ちの回は補えない。途切れが2秒を超えた回は「やり直し推奨」になる
- Safari で同じことが起きるかは未確認（実機で確かめる手順の6）

## 開く方法

このディレクトリを静的WebサイトとしてHTTPS配信し、スマートフォンのSafari / Chromeで直接開く。スマートフォンからPCの `http://192.168.x.x` に接続するだけではセンサーを利用できない。LINE等のアプリ内ブラウザは対象外。

PCでの表示には、このディレクトリで `python3 -m http.server 8000` を実行し、PC自身の `http://localhost:8000` を開く。スマートフォンでは公開ページ（GitHub Pages）を開く。

追加のビルド工程はない。配信対象は index.html、styles.css、app.js、geometry.js、vision-worker.js。研究資料や計測データは配信ディレクトリに置かない。

## 操作

### カメラ校正（iPhone 1台につき1回、1〜2分）

1. スマホをスタンドに縦向きで立て、「カメラ・IMUを開始」を押す（計測と同じ解像度で校正するため）
2. 「2 カメラ校正」でマスの実寸（4マス分を定規で測って4で割った値）を入れ、「校正を始める」
3. ボードを前で20〜30秒ゆっくり動かす（30〜50 cm、向きと位置を変えながら、少し斜めに）。採用のたびに音が鳴り、映像の下に「○ / 15 枚」が出る
4. 15枚そろうと計算し、再投影誤差1 px未満なら合格して保存する。「校正結果をJSONで保存」で書き出せる

### 被験者ごと（1回の記録）

1. 縦向き・着座で「カメラ・IMUを開始」を押し、カメラと動作・方向を許可する
2. 「3 セットアップと基準姿勢」で持ち方を確かめ（条件を選べば合わせて切り替わる）、固定では映像の上の表示に従って ①傾き → ②高さ → ③距離 を合わせる。3つとも緑になると音が鳴る
3. 被験者に基準の姿勢をとってもらい、「この姿勢を基準にする（3秒）」
4. 「5 計測を記録」で被験者ID・条件・回番号を確かめて「記録開始」→ CVAカメラの案内 → 「記録停止」
5. 品質判定（OK／やり直し推奨）を確かめ、CSVと全記録JSONを保存する

カメラ画像は送信・保存しない。開始時にjsDelivrとGoogleのストレージからライブラリ・モデルを取得するため通信が必要。完全オフライン版ではない。
数値は最大20分間記録。約5秒ごとにIndexedDBへ途中退避する。モバイルOSによる終了直前の書き込みは保証しない。終了時に必ずダウンロードを確認する。自動退避できない場合は画面に表示する。

## 計算方法と限界

### 虹彩径と距離

- 478点のうち左右の虹彩外周を使用。各目の2本の直径の大きい方を取り、その左右平均を p とする。楕円の真の長軸を厳密に求める方法ではない。
- 未校正：仮の水平画角60度、虹彩径11.7 mmから `Z[cm] = f[px] × D[mm] / p[px] / 10`。両仮定は設定変更可能。機種固有の焦点距離・画角を取得した値ではない。
- 1点校正：`K = 実測距離[cm] × 校正時の虹彩径[px]` を保持し、`Z = K/p`。焦点距離と虹彩実寸を個別に同定する方法ではない。
- 基準からの距離比：`p_baseline/p × 100%`。未校正でも表示する。
- Zは光軸方向の奥行き。中心付近で校正して直線距離との違いを小さくするが、主点・歪み・虹彩個人差・視線・オートフォーカス・クロップの影響を解決したわけではない。
- 手持ちでは端末と頭の並進を分離できない。距離変化をCVA変化や頭部前方変位と同一視しない。

### 頭部回転とIMU

MediaPipeの顔変換行列から回転軸を抽出。元デモと同じ行列格納順の推定を使用し、格納順フラグと元行列をJSONに保存する。
DeviceOrientationの `Rz(alpha) Rx(beta) Ry(gamma)` から、端末座標で表した鉛直上向きベクトルを求める：

`u = (-cos(beta)sin(gamma), sin(beta), cos(beta)cos(gamma))`

未反転の前面カメラの顔正面ベクトルを n として、端末座標へ `n_device = (-n_x, n_y, -n_z)` と変換し、下向きを正とする傾き `h = -asin(dot(n_device, u))` を算出。表示値は `h - h_baseline`。縦持ちのみ。鏡像処理はCSS表示に限定する。

これは顔の正面軸の鉛直に対する傾きであり、C7–耳珠ベクトルの角度ではない。実端末で方向・符号・端末を回したときの相殺を確認する必要がある。未受信のIMUを0度として補完しない。

仮CVAは計算モデルの合意待ち。基準姿勢取得だけで実測CVAは分からない。

### 時刻と品質

画像を処理に渡す直前のperformance.nowを時刻とし、その時点で最新の方向イベントを対応付ける。補間・厳密な同期は未実装。画像のハードウェア露光時刻ではない。IMUのイベント時刻と受信時刻、動画のcurrentTime、推論時間、結果受信時刻を別々に保存する。
方向情報が250 msより古い場合は頭部の重力補正を表示しない。顔未検出や設定範囲外の回転、虹彩径不足、目の開き不足、左右径の大きな不一致を除外する。これらは暫定しきい値で、精度を保証しない。

顔推定は原則Workerで実行。非対応時はメインスレッドへ切り替え、推定頻度を抑える。主処理が遅い場合に古い画像を蓄積しない。画面非表示時は記録を停止し、自動再開しない。縦横変更時は基準を無効化する。

## 実機で確かめる手順（0.2.0）

iPhone 15 の Safari で、上から順に確かめる。

1. **校正の読み込み**：「校正を始める」で OpenCV.js が読み込まれるか（初回は数十秒）。カメラの解像度（「カメラ：○×○」）を控える
2. **校正の採用**：ボードを動かすと音が鳴って枚数が増えるか。15枚で「合格」になり、f と再投影誤差が出るか。白黒反転のボードで角が出ないときは知らせる（模様の版の違いを自動で1回試す）
3. **f の妥当性**：f から求まる水平画角（校正結果のJSONの `hfovDeg`）が、内カメラとしてありそうな値か。同じ校正を2回して f が1%以内にそろうか
4. **傾きの向き**：スタンドで、端末の上端を奥へ倒すと「上端が奥へ」、画面を見て左へ傾けると「上端が左に」になるか。±1°で緑になるか
5. **高さと距離**：横線に目を合わせると「目の高さです」になるか。メジャーでレンズ〜目を40 cmにしたとき、距離の表示が40 cm前後か（虹彩の実寸を11.7 mmと仮定しているので、±2 cm程度はありうる）
6. **IMUの途切れ**：1分ほど記録し、終了時の「IMUの途切れ」の回数と最長を見る。Chrome と Safari で違うかも比べる
7. **予備の経路**：記録の JSON で `imuSource` が `orientation` のフレームと `motion` のフレームがあれば、その前後で h が連続しているか。`gravitySignSource` が `orientation` になっているか
8. **スタンドの動き**：固定で記録中にスタンドを軽く押して傾け、終了時に「スタンドの傾きが基準から1°以上変わりました」が出るか
9. **品質判定**：手を顔の前にかざして3秒隠すと「やり直し推奨（h が途切れた、時刻つき）」になるか
10. **ファイル名と保存**：`P01_fixed1_posture_<時刻>.json` で「ファイル」に保存できるか
11. **画面の消灯**：3分の記録中に画面が暗くならないか

## 実機で確認する項目（0.1.1から、未実施）

両OSでの権限、モデル読み込み、前面カメラ選択、顔の上下と表示符号、頭を固定して端末のみ傾けたときの補正、正面での既知距離比較、遮眼・顔逸脱・画面中断、CSV/JSONの保存先、連続使用中の発熱・欠測を確認する。Web標準の焦点距離やLiDAR取得を仮定していない。
