### 4. まぶたの判定
| 変更 | 内容 |
|---|---|
| `irisOccluded` | 決まったしきい値（`eyeOpenMin` < 0.15）ではなく、**基準を記録したときの `eyeOpenMin` の中央値に対する比が 0.6 未満**（`IRIS_OCCLUSION.ratio`）。基準の値がないときは今までの 0.15 |
| 追加の列 | `eyeOpenRatio`（比）、`irisOccludedFixed`（今までの 0.15 の判定、比べる用） |
| meta | `irisOcclusion`（方法・比・基準の値・固定のしきい値）、`baseline.eyeOpenMinMedian` |

**P02 の記録で試した結果（重要）**：P02 の最初の基準の `eyeOpenMin` の中央値は 0.24〜0.28 で、0.6倍は 0.145〜0.17。**固定の 0.15 とほぼ同じ**なので、基準の区間で「隠れている」と判定される割合は 25〜36% のまま変わらない（比を 0.4 にしても、0.5秒の中央値にしても 23〜33%）。P02 の目の開きが小さいのではなく、基準の間にも 0.15 未満が 0.2〜2秒ほど続く場面が多い（瞬き・目線の低下、または目の点の検出のぶれ）。しきい値の選び方では解決しないので、`eyeOpenRatio` を残し、除外の決め方は解析で検討する。

## 0.3.1：セットアップを緩める（2026-11-15）

0.2.x・0.3.0 では、傾き±1°・高さ±1 cm・距離±1 cm を同時に満たすのがかなり難しかった。高さと距離は被験者の呼吸や頭の小さな動きでも変わり、虹彩の実寸の仮定（11.7 mm）だけで距離に±2 cm 程度の誤差があるので、±1 cm は測れる精度より細かかった。

| 変更 | 内容 |
|---|---|
| 許容 | 傾き **±2°**、高さ **±2 cm**、距離 **±3 cm**（`SETUP` の定数） |
| 平滑化 | 判定と表示は直近1秒の中央値（数値のちらつきを抑える） |
| ヒステリシス | 一度緑になった項目は、許容の1.5倍（傾き3°・高さ3 cm・距離4.5 cm）を超えるまで緑のまま |
| 目安であることの表示 | 「緑にならなくても基準は記録できます（実際の値は記録に残ります）」。基準のボタンは、もともとセットアップの合格を条件にしていない |

基準を記録したときの実際の値（傾き・高さのずれ・距離・合格していたか）は、今までどおり `meta.setup` に残る。

## 0.2.1：dual_test3 を受けた修正（2026-11-13）

dual_test3（P01）では3回ともやり直し推奨になったが、多くは判定の側の問題だった（固定のうつむくで顔がカメラから外れた、9分前・16分前の基準と比べてスタンドが「動いた」）。

| 変更 | 内容 |
|---|---|
| h の途切れの判定 | 5秒窓の割合と最長の途切れは、**顔が写っている（`faceDetected`）フレームだけ**で計算する（「顔が写っているのに h が出ない」＝IMU や計算の失敗を見つけるため）。しきい値（5秒・70%・2秒）は同じ |
| 顔が写っていない時間 | 判定とは別に「注意」として時刻つきで表示（例「61.4〜74.3秒（12.9秒）」）。0.5秒以上のものだけ。`meta.quality.noFace` |
| スタンドの動き | 比べる基準を**記録開始時の1秒間の上向きの平均**に（`meta.standReference`）。しきい値は **2°を超えたら**（戻ったとみなすのは1°未満）。最大値とその時刻を `meta.quality.standMoved` に。列 `standTiltChangeFromStartDeg` を追加（`standTiltChangeDeg` は基準からの角度のまま残す） |
| 古い基準の警告 | 記録開始時に、基準（「この姿勢を基準にする」）が**5分以上前**なら、記録中の画面と状態の欄に「基準を取り直してください」と出し、イベント `baseline_stale` を残す。終了時の判定は「注意」 |
| `irisOccluded` | `eyeOpenMin` < 0.15 のフレームで `true`（まぶたが虹彩を隠し、`zFocalCm` が +4〜5 cm と大きく出るため。`zFocalCm` は消さない。除外は解析で） |
| 記録中の画面 | 記録中はページを固定（スクロールできない、`touch-action: none`）し、全面に「**画面に触れないでください**」と経過時間を表示。停止は**1秒の長押し**（短く触れただけでは止まらない） |
| タッチの記録 | `touchstart`・`touchend`・`touchcancel`・`pointerdown`・`pointerup`・`pointercancel`・`scroll` を時刻つきで `inputs` に記録（記録開始ボタンを含めるため、開始前5秒も残す） |
| IMUの途切れとタッチ | 終了時に、方向・加速度の途切れ（250 ms超）ごとに、前後0.3秒以内にタッチ・スクロールがあったかを表示（`meta.quality.imuGapList`、`imuGaps.*.withTouch`） |
| 判定の表示 | 「OK」「**注意**」「やり直し推奨」の3段階に。「注意」はやり直さなくてよい（`warnings`） |

予備実験（dual_test3）の固定の回では、IMUの途切れが記録開始の直後と停止の直前（どちらもボタンを押した時間帯）に集中していた。iOS の WebKit がタッチやスクロールの処理中にセンサーのイベントの配送を止めている、という仮説を確かめるため、タッチを記録する（確定ではない）。

### IMU の途切れの原因（予備実験のデータから）

dual_test1・2 では、方向と加速度のイベントが**同じ時刻に同じ長さだけ**止まっていた（1回目：250 ms超が22回・最長5.0秒、2回目：6回・最長3.4秒）。イベント自体の時刻（`eventTimestamp`）も同じだけ空いていたので、ブラウザの処理が詰まって遅れたのではなく、イベントが発生していなかった。カメラのフレームはその間も処理されていた（途切れ0回）。ブラウザは iPhone の Chrome（CriOS 155、中身は WebKit）。

- 加速度の予備の経路は、方向だけが来ない場合には効くが、**この途切れは埋められない**（両方が同時に止まるため）
- 固定の回は、基準時の上向きで h を補う（`headInclinationFixedUp`）。スタンドが動いていないことは、IMUが届いている間の判定で確かめる（0.2.1 から、記録開始時と比べて2°）
- 手持ちの回は補えない。途切れが2秒を超えた回は「やり直し推奨」になる
- Safari で同じことが起きるかは未確認（実機で確かめる手順の6）

## 操作

### カメラ校正（iPhone 1台につき1回、1〜2分）

1. スマホをスタンドに縦向きで立て、「カメラ・IMUを開始」を押す（計測と同じ解像度で校正するため）
2. 「2 カメラ校正」でマスの実寸（4マス分を定規で測って4で割った値）を入れ、「校正を始める」
3. ボードを前で20〜30秒ゆっくり動かす（30〜50 cm、向きと位置を変えながら、少し斜めに）。採用のたびに音が鳴り、映像の下に「○ / 15 枚」が出る
4. 15枚そろうと計算し、再投影誤差1 px未満なら合格して保存する。「校正結果をJSONで保存」で書き出せる

### 被験者ごと（1回の記録）

1. 縦向き・着座で「カメラ・IMUを開始」を押し、カメラと動作・方向を許可する
2. 「3 セットアップと基準姿勢」で持ち方を確かめ（条件を選べば合わせて切り替わる）、固定では映像の上の表示に従って ①傾き → ②高さ → ③距離 を合わせる。3つとも緑になると音が鳴る
3. 被験者に基準の姿勢をとってもらい、「この姿勢を基準にする（3秒）」
4. 「5 計測を記録」で被験者ID・条件・回番号を確かめて「記録開始」→ CVAカメラの案内 → 「記録停止」を**2秒長押し**。記録中は画面に触れない（全画面の計測画面に切り替わる）。**基準は回ごとに取り直す**（5分以上前の基準だと警告が出る）
5. 品質判定（OK／注意／やり直し推奨）を確かめ、CSVと全記録JSONを保存する

カメラ画像は送信・保存しない。開始時にjsDelivrとGoogleのストレージからライブラリ・モデルを取得するため通信が必要。完全オフライン版ではない。
数値は最大20分間記録。約5秒ごとにIndexedDBへ途中退避する。モバイルOSによる終了直前の書き込みは保証しない。終了時に必ずダウンロードを確認する。自動退避できない場合は画面に表示する。

## 計算方法と限界

### 虹彩径と距離

- 478点のうち左右の虹彩外周を使用。各目の2本の直径の大きい方を取り、その左右平均を p とする。楕円の真の長軸を厳密に求める方法ではない。
- 未校正：仮の水平画角60度、虹彩径11.7 mmから `Z[cm] = f[px] × D[mm] / p[px] / 10`。両仮定は設定変更可能。機種固有の焦点距離・画角を取得した値ではない。
- 1点校正：`K = 実測距離[cm] × 校正時の虹彩径[px]` を保持し、`Z = K/p`。焦点距離と虹彩実寸を個別に同定する方法ではない。
- 基準からの距離比：`p_baseline/p × 100%`。未校正でも表示する。
- Zは光軸方向の奥行き。中心付近で校正して直線距離との違いを小さくするが、主点・歪み・虹彩個人差・視線・オートフォーカス・クロップの影響を解決したわけではない。
- 手持ちでは端末と頭の並進を分離できない。距離変化をCVA変化や頭部前方変位と同一視しない。

### 頭部回転とIMU

MediaPipeの顔変換行列から回転軸を抽出。元デモと同じ行列格納順の推定を使用し、格納順フラグと元行列をJSONに保存する。
DeviceOrientationの `Rz(alpha) Rx(beta) Ry(gamma)` から、端末座標で表した鉛直上向きベクトルを求める：

`u = (-cos(beta)sin(gamma), sin(beta), cos(beta)cos(gamma))`

未反転の前面カメラの顔正面ベクトルを n として、端末座標へ `n_device = (-n_x, n_y, -n_z)` と変換し、下向きを正とする傾き `h = -asin(dot(n_device, u))` を算出。表示値は `h - h_baseline`。縦持ちのみ。鏡像処理はCSS表示に限定する。

これは顔の正面軸の鉛直に対する傾きであり、C7–耳珠ベクトルの角度ではない。実端末で方向・符号・端末を回したときの相殺を確認する必要がある。未受信のIMUを0度として補完しない。

仮CVAは計算モデルの合意待ち。基準姿勢取得だけで実測CVAは分からない。

### 時刻と品質

画像を処理に渡す直前のperformance.nowを時刻とし、その時点で最新の方向イベントを対応付ける。補間・厳密な同期は未実装。画像のハードウェア露光時刻ではない。IMUのイベント時刻と受信時刻、動画のcurrentTime、推論時間、結果受信時刻を別々に保存する。
方向情報が250 msより古い場合は頭部の重力補正を表示しない。顔未検出や設定範囲外の回転、虹彩径不足、目の開き不足、左右径の大きな不一致を除外する。これらは暫定しきい値で、精度を保証しない。

顔推定は原則Workerで実行。非対応時はメインスレッドへ切り替え、推定頻度を抑える。主処理が遅い場合に古い画像を蓄積しない。画面非表示時は記録を停止し、自動再開しない。縦横変更時は基準を無効化する。

## 実機で確かめる手順（0.2.0）

iPhone 15 の Safari で、上から順に確かめる。

1. **校正の読み込み**：「校正を始める」で OpenCV.js が読み込まれるか（初回は数十秒）。カメラの解像度（「カメラ：○×○」）を控える
2. **校正の採用**：新しいボード（白黒反転なし、48 mm）を動かすと音が鳴って枚数が増えるか。15枚で「合格」になり、f と再投影誤差が出るか。角が出ないときは知らせる（模様の版の違いを自動で1回試す）
3. **f の妥当性**：f から求まる水平画角（校正結果のJSONの `hfovDeg`）が、内カメラとしてありそうな値か。同じ校正を2回して f が1%以内にそろうか
4. **傾きの向き**：スタンドで、端末の上端を奥へ倒すと「上端が奥へ」、画面を見て左へ傾けると「上端が左に」になるか。±2°で緑になるか（0.3.1）
5. **高さと距離**：横線に目を合わせると「目の高さです」になるか。メジャーでレンズ〜目を40 cmにしたとき、距離の表示が40 cm前後か（虹彩の実寸を11.7 mmと仮定しているので、±2 cm程度はありうる）
6. **IMUの途切れ**：1分ほど記録し、終了時の「IMUの途切れ」の回数と最長を見る。Chrome と Safari で違うかも比べる
7. **予備の経路**：記録の JSON で `imuSource` が `orientation` のフレームと `motion` のフレームがあれば、その前後で h が連続しているか。`gravitySignSource` が `orientation` になっているか
8. **スタンドの動き**（0.2.1 で変更）：固定で記録中にスタンドを軽く押して3°ほど傾け、終了時に「スタンドの傾きが記録開始時から 2°を超えて変わりました（時刻つき）」が出るか。触れずに置いたままなら出ないか
9. **品質判定**（0.2.1 で変更）：手を顔の前にかざして3秒隠すと、やり直し推奨ではなく「注意：顔が写っていない時間 ○〜○秒」になるか
10. **ファイル名と保存**：`P01_fixed1_posture_<時刻>.json` で「ファイル」に保存できるか
11. **画面の消灯**：3分の記録中に画面が暗くならないか

16. **顔が写っていない時間**：固定で、新しい声かけ（CVAカメラ 0.5.1）で「うつむく」をして、終了時に「顔が写っていない時間」が出ないか（出たら、その時刻がうつむく区間か）
17. **目線だけ下げる**：JSON で、目線だけ下げる区間の `irisOccluded` が `true` になり、そのフレームの `zFocalCm` が大きく出ているか
